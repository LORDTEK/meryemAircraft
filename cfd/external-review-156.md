#### 3. My independent proposal for the next stage

I would **not make “merge sections” the primary operation**.

I would use a **finding-home compression stage**, with merging as an optional consequence.

The distinction matters because a section can contain two different kinds of repetition:

1. a repeated **finding** that genuinely needs only one evidentiary home; or
2. a repeated **argument step** whose repetition is rhetorically necessary because it connects two different parts of the paper.

W-2 demonstrated exactly why blindly merging repetitions is dangerous: the statement in §5.1 was not merely an echo of §1; it performed the combination step of the argument.

So my method would be:

###### Phase A — Build a redundancy/finding-home map

For each repeated finding:

**Finding → occurrences → evidentiary home → interpretive home → downstream use**

I would classify each occurrence as:

* **H** — home: evidence and interpretation belong here.
* **C** — clause: retain only enough to connect the argument.
* **P** — pointer: direct reader to the home.
* **K** — keep: repetition is structurally necessary because this occurrence performs a distinct argumentative job.
* **S** — supplement: derivation/audit material can leave the body.

This is slightly different from “merge the sections.”

###### Phase B — Decide at finding level before section level

Only after the repeated finding-blocks are classified would I ask:

> Do enough neighboring blocks now have the same home that the sections themselves should merge?

That prevents the section structure from determining the answer prematurely.

###### Phase C — Compress one cluster at a time

For each cluster:

1. freeze its current text;
2. designate the home;
3. identify every occurrence that survives;
4. reduce non-home occurrences to clause/pointer/keep;
5. move only derivation/audit residue;
6. run **receipt + first-occurrence + antecedent + number identity** checks immediately;
7. only then proceed to the next cluster.

I would **not merge multiple sections in one round**.

##### 3. My method for the next stage

I propose something genuinely different from the moderator’s draft, because the author asked for independent proposals and I think the difference matters.

**Home-assignment first; clause-cutting as the primary unit; block-moving second; merging only as a last resort.**

The moderator’s method is *“examine which sections can be merged; from merged sections, the residual sentences move to the supplement.”* I propose to invert the order. Merging sections is the largest operation available, and it is the one that produces the W-1 class of defect (a pointer whose receiver moved). The W-2 discussion showed that the same finding can have a different function in each section it appears in. Merging sections destroys the function; assigning homes preserves it.

**The method, in order:**

1. **Build the redundancy map with function labels.** For every finding stated in more than one place, record each occurrence’s function: *definition / argument step / consequence / boundary / debt*. The moderator’s map has the finding and its home; mine adds the function. This is what makes the next step possible.

2. **For each cluster, choose the home and the residue form.** The residue forms, in order of preference:
   - **Cut to a pointer** — where the non-home occurrence is one sentence or clause that names the finding without arguing it. The pointer is to the home.
   - **Cut to a clause** — where the non-home occurrence carries a local qualification or direction that the home does not carry. The clause names the finding and the local qualification; the home carries the argument.
   - **Move the block to the supplement** — where the non-home occurrence is a full block whose content is entirely carried by the home. The block goes to the supplement under its original heading.
   - **Merge the sections** — only where the redundancy map shows two sections cannot stand apart because each depends on the other’s evidence.

3. **Order of home-assignments.** Calculations first (7.1–7.4 and their restatements in 4 and 8), then boundary (6.1, 6.2, 8, 9), then framework (2.1–2.3), then the architecture (1, 3, 4’s claim, 5.1, 5.2). This follows the author’s Round 67 rule.

4. **After each home-assignment, run on the affected sections only:** receipts (including *above* and *below*), definitions before use, protected sentences, nothing lost. Not the whole text each time. The whole-text sweep runs once, at the end.

5. **Merging, if any, comes last.** A section-merge is a structural change to the assembled view, and it should not happen until the redundancy map has been worked through cluster by cluster. If the map shows that clause-cutting already achieves the length reduction, no section needs to merge.

6. **The citation map (H-2) is built after the home-assignments and before any section-merge.** Home-assignments do not change section numbers; section-merges do. Building the map after home-assignments but before merges fixes the citations before the section numbers move, and any merge then updates a known map rather than building a new one.

7. **Freeze continues.** A new rule or audit type only with a named defect. The W-1 precedent applies: a merge is a split in reverse, and it produces the same class of defect.

**Why this differs from the moderator’s draft.** The moderator’s method starts from sections and asks which merge. Mine starts from findings and asks where each belongs. The moderator’s map is cluster-level; mine is cluster-and-function-level. Both arrive at a shorter paper; mine arrives at it by moving less, because clause-cutting and pointer-cut are smaller operations than merging.

**One risk, stated plainly.** Clause-cutting can lose a local qualification that the home does not carry. That is why the residue-form choice is by function, not by length. The W-2 case is the model: Section 5.1’s contribution statement was not a repetition of Section 1’s; it was the argument step. My method would have labelled it *argument step* and left it as it is.
